* **DeepSeek** — основной AI-ассистент на протяжении всего задания. Использовался для объяснения работы инструментов и оформления Markdown-файлов.

## Для каких задач использовался AI

* Диагностика ошибок Docker/Dagger по логам (монтирование файлов, сети, права доступа).
* Оформление `README.md` и `AI_REVIEW.md` (структура, разделы, команды).

## 5 примеров некорректных/неоптимальных решений AI

### Монтирование отдельного файла `prometheus.yml` (долгая борьба)
**Проблема:** AI предложил `volumes: - ./prometheus.yml:/etc/prometheus/prometheus.yml:ro`. Внутри Dagger-контейнера Docker создавал директорию на месте файла.
**Обнаружение:** Логи Prometheus: `read /etc/prometheus/prometheus.yml: is a directory`.
**Решение:** Перепробовали несколько подходов: `with_file`, `with_mounted_file`, `configs`. В итоге остановились на монтировании всей папки `monitoring` и использовании `configs` с inline-контентом. Это исключило создание директорий.

### `mysqld-exporter` и `DATA_SOURCE_NAME`
**Проблема:** AI предложил использовать переменную `DATA_SOURCE_NAME` для подключения к MariaDB. В версии 0.20+ экспортер перестал её поддерживать.
**Обнаружение:** Логи: `no user specified in section or parent`.
**Решение:** Заменили на флаги `--mysqld.username` и `--mysqld.address` в `command`.

### Настройка Grafana через API по имени контейнера
**Проблема:** AI предложил обращаться к Grafana по адресу `http://grafana:3000`. Внутри Dagger-контейнера это имя не резолвилось.
**Обнаружение:** `curl: (6) Could not resolve host: grafana`.
**Решение:** Использовали `host.docker.internal:3000` для доступа к Grafana с хоста.

### Передача JSON-модели дашборда как строки
**Проблема:** AI предложил передавать JSON дашборда через `-d '...'`. Это приводило к ошибкам экранирования кавычек.
**Обнаружение:** Ошибка парсинга JSON на стороне Grafana.
**Решение:** Передали JSON как файл (`--data-binary @/dashboard.json`), смонтировав его через `with_mounted_file`.

## Отдельно про работу с файлами и Markdown

* **Файлы для Docker Compose:** Больше всего времени ушло на то, чтобы заставить Docker внутри Dagger-контейнера «увидеть» файлы `prometheus.yml` и `mysql-exporter.cnf`. AI предлагал разные варианты (монтирование файла, монтирование папки, `configs`), но каждый раз всплывали нюансы WSL2 и Docker Desktop. В итоге помогло монтирование всей папки и отказ от отдельных файлов в пользу `configs` с inline-контентом.
* **Синтаксис:** AI помогал с синтаксисом Python SDK Dagger (правильные типы аргументов, `with_unix_socket`, `with_mounted_file`), синтаксисом YAML для Compose и JSON для дашборда.
* **Написание Markdown:** AI сгенерировал структуру и текст `README.md` и `AI_REVIEW.md`, включая команды запуска, разделы про архитектуру и примеры ошибок.

## Вывод
AI (DeepSeek) значительно ускорил написание шаблонного кода, конфигов и документации, но потребовал ручной проверки и адаптации под конкретные версии Dagger, Docker Compose и экспортеров. Все ключевые архитектурные решения (проброс сокета, разделение слоёв, валидация) принимались и проверялись вручную. Наибольшая сложность была не в коде, а в том, чтобы заставить файлы конфигурации корректно «доехать» до контейнеров через Dagger и Docker Desktop на WSL2.
